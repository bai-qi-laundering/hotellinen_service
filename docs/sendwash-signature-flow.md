# 送洗品項共用原本的逐項簽名流程

送洗單只提供預填數量。index.html 的所有品項共用同一個左右兩格卡片、openSign 簽名板、openCalc 計算機及 firebaseSubmit 儲存入口。已移除整張送洗單的專用簽名視窗。

每個品項操作：左側第一步簽名 → 確認或修改預填數量 → 確定並儲存；洗完後右側第二步複點簽名 → 確認或修改複點數量 → 儲存。備註欄仍在卡片下方，點收前就能儲存，點收時會一併保留。

每個品項的點收交易只核對自己的來源品項與申報數量，不以整張來源单物件的 JSON 鍵值排列或其他品項修改判斷失敗。真正的此品項數量變更、既有人工資料、他人已點收、已完成複點等情況仍會拒絕覆蓋並提示重新載入。

来源單透過 receivedItems 逐項記錄接收狀態。已開始接收的來源單鎖定飯店端修改；其他未接收品項仍可逐一點收。所有本次有填數量的品項接收完成後才設定整單 acceptedAt。相同單筆儲存重試不會重复加總。

舊版已簽名資料不自動刪除或重設。此變更不用更新 Apps Script。財務及物流的數量讀取規則維持目前版本。

離線驗證：tests/sendwash-per-item.cjs 測試原 openSign → confirmSignature → calcConfirm → firebaseSubmit 的完整函式串接、逐項交易、JSON 鍵值順序變更、其他品項更新、選定品項真正變更、重試與備註保存。測試不接觸正式資料庫。
