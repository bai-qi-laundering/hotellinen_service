# 百麒對帳單送件中心｜獨立新增功能規格（待整合）
此文件位於 feature/statement-dispatch-center 分支，不更動正式版 finance.html。

## 不可破壞的既有行為
- 原本飯店專屬結帳日、簽名、財務調整、計價、出貨資料、Excel 匯出保持不變。
- 不接受員工上傳或直接修改 Excel；一律返回財務系統修改，重新產出。
- 發票功能尚未啟用；只預留「待開票」狀態及版本金額。

## 同一頁面（桌面與 iPhone）
每張飯店結帳卡顯示飯店、週期、LINE 收件名稱、金額、版本、狀態。
- 「核對帳單」：開啟唯讀 PDF，手機全螢幕，桌面可開新分頁；不在清單下展開。
- 「確認送出」：使用同版本 XLSX。iPhone 嘗試 Web Share API 分享檔案至 LINE；若不支援則下載。桌面下載 XLSX 後，員工自行上傳 LINE 聊天室。
- LINE 個人聊天室不提供可靠的外部網頁送達回執，紀錄名稱須為「員工登記已寄送」，不得宣稱 LINE 已成功送達。
- 確認送出應在使用者完成手動傳送後才登記；下載或開啟分享面板不等於已送達。

## 版本與檔案一致性
- 每家飯店 + 結帳起迄日期形成唯一結帳案件；每次有效內容變更產生不可變的版本快照。
- PDF 與 XLSX 從同一份結帳快照產生；儲存檔案 SHA-256、版本、生成時間、品項/部門/數量/單價/稅/總額摘要。
- 驗證兩種輸出與快照的每筆明細一致；失敗則禁止發布和送件。
- 同一內容重跑不增加版本，不重置已寄送。
- V1 已寄送後若財務重算得到 V2，顯示「新版待重寄」；保留 V1 寄送紀錄，V2 未登記前不得進入待開票。
- 送出時後端使用版本號條件檢查，避免使用者打開 V1 後另一人產生 V2 的競態。
- 待開票只能參照目前最新版且已登記寄送的版本；已開票後變更須走獨立差異處理，不得直接覆寫已開票資料。

## 自動觸發與整合前檢查
1. 盤點 finance.html 的資料讀取、飯店結帳日期與簽名完成條件，確定可靠的後端事件來源。
2. 目前 XLSX 主要在瀏覽器產生，需選定可安全保存檔案與供手機讀取的後端（例如既有 NAS 服務或 Firebase Storage），確認權限與持久化。
3. 決定 PDF 轉檔方案，確認字型、頁碼、多部門報表與 Excel 一致性驗證。
4. 新增後端版本 API、不可變檔案保存、送件登記與發票候選資料；再建立獨立頁面。
5. 實機測試 iPhone LINE 分享 XLSX 與 Windows 下載，並測試重算、重寄、同時開啟、離線、權限與失敗回滾。

## 驗收門檻
在後端保存、實際 XLSX/PDF 生成與版本比對完成前，不得把 UI 模擬當成正式送件功能，也不得修改正式財務資料。
